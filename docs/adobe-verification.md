# Adobe 请求核验记录

核验日期：2026 年 10 月 14 日。下面区分已获得图片的结果、上游明确返回的限制，以及仍需验证的部分。原始 Cookie、令牌、账号密码和签名图片地址均不放入仓库。

## 请求与页面依据

生图请求为 `POST https://firefly-3p.ff.adobe.io/v2/3p-images/generate-async`。Firefly 页面使用 Bearer、`x-api-key: clio-playground-web` 和页面认证服务提供的 `x-arp-session-id`。

页面 `bundle-0.js` 的认证服务定义公开了 `arpSessionToken`，`bundle-1.js` 的认证适配层将页面采集值传入该服务。浏览器同步读取当前页面的服务对象，不固定网页发布时可能改变的模块编号，不自行构造风险凭据。

`x-nonce` 由 `userId + "-" + prompt.slice(0, 256)` 经 UTF-8 编码和 SHA-256 得到。Go 实现保留 JavaScript 按 UTF-16 截断的行为，回归覆盖代理对边界。

参考项目中的 Express 请求路线使用不同的客户端标识和页面来源，不能直接混用到 Firefly 路线。GPT 明确尺寸使用顶层 `size`，非自动模式的 `modelSpecificPayload` 为空；画质通过 `generationSettings.detailLevel` 的 1、3、5 表示。

| Sunburst | `gpt-image-2.5-prism` | 3504×2336 | 43.784 秒 |

参考图复用实际生成的陶瓷碗图片。OpenAI `/v1/images/edits` 的文件上传得到 1024×1024 图片，完整耗时 29.940 秒；`/v1/chat/completions` 的参考图和流式输出得到 1024×1024 图片，完整耗时 29.013 秒，并收到 `[DONE]`。三条参考图链路均保存了参考图和上传接口记录，生成文件 URL 再次读取均返回 200。

## 尺寸限制与未确认项

三款模型提交 4096×4096 均返回 HTTP 400，正文明确要求最长边不超过 3840、总像素不超过 8,294,400。服务据此在调用前校验尺寸，并采用 16 像素对齐的默认尺寸映射。

4K 的默认方形为 2880×2880，3:2 为 3504×2336，GPT Image 2 的 16:9 为 3840×2160。Sunburst、Flare 的 3504×2336 已在同步有效会话后实际生成成功。2K、4K 自动比例尚未获得有效输出，当前要求明确画面比例，避免省略尺寸后回退默认档位。

## 登录与 Cookie 修正

Cookie 通过 IMS 换取令牌时不要求先提供用户标识，使用响应中的真实身份并核对已有账号。更新响应的 Set-Cookie 会合并回账号，下次续期继续使用更新后的值。

浏览器中存在 `.adobe.com`、`.adobelogin.com`、`.services.adobe.com` 的同名 Cookie，直接按数组顺序合并会让旧值覆盖目标请求实际需要的值。同步改为读取 IMS 目标 URL 可发送的 Cookie，按域和路径具体程度确定同名值，并验证输入顺序不影响结果。

IMS 曾以 HTTP 200 返回 `invalid_credentials`，服务现在将其识别为登录失效。认证失败、生成 408 和风险会话未初始化分别记录；不能仅凭 408 判断 Cookie 已失效，也不能把获取令牌成功标记为生图成功。账号在获得凭据后为待验证，真实生成成功后才显示可用。

同一个账号在两个浏览器会话中曾分别返回 408 和成功异步任务。不能仅凭 408 判断账号到期、积分不足或上游拥堵。定位到显式同步误保留旧 ARP 后，改为采用本次页面的风险会话，随后的四项正式接口测试全部成功。仅通过 IMS 直接续期时保留原 ARP；浏览器同步及补全则更新 ARP。

同步只读取页面正常生成的风险会话，拒绝初始 sid 值、非法编码和缺失供应商凭据的值；不自行生成凭据。IMS 已完成轮换但后续取消或补全失败时，保存最近一次已确认的同账号凭据。Adobe 正常登录要求邮箱验证码或人机验证时，由账号持有人完成该步骤后再同步。

当前页面香蕉模型菜单为 Nano Banana 2 和 Nano Banana Pro，模型目录据此发布。

## 日志与保存

生成日志增加有界、脱敏的请求头、请求 JSON、响应头和响应 JSON，图片内容以文件保存。生成前触发的 IMS 刷新请求也归入同一条记录。现有清理策略升级时暂停，旧日志与图片继续保留；管理员之后主动修改的策略正常生效。
